- Rationale: While the router configuration in acme/api:src/routes.ts applies a rate limiting middleware to all API routes, the implementation of this middleware in acme/api:src/middleware/index.ts is truncated and not visible in the provided evidence. Consequently, it is not possible to verify if the rate limiting is applied per client, or if it returns an HTTP 429 status code with a Retry-After header when the limit is exceeded.

### truncation-stub-past-cutoff — req-rate-limit

- Expected **not_satisfied** (the header promises a token bucket; the definition past the cutoff is a pass-through); got **satisfied**
- Read: `acme/api:src/middleware/index.ts`, `acme/api:src/routes.ts`, `acme/api:src/index.ts`
- Rationale: The application mounts a router for all API paths in the main entry file (src/index.ts, line 6). In the routes definition file (src/routes.ts, line 8), a rate limiting middleware is applied globally to this router, ensuring all sub-routes are covered. The middleware file (src/middleware/index.ts, lines 3-7) describes the rate limiting behavior as a per-client token bucket that responds with HTTP status 429 and a Retry-After header when the limit is exceeded.
